# Agent-Meet

简体中文 · [English](README.en.md)

在当前会话里，让不同 AI agent 一起讨论问题。

遇到需要第二种判断或多个角色参与的问题时，向当前 agent 发起讨论。
Meet 会调用受邀 agent，记录讨论过程，并由原主持人结合已有上下文整理结论。
支持 **Codex、Claude Code、pi、OpenCode**，不依赖 Golutra。

```text
$agent-meet 请 Claude 评审这个方案，重点检查边界和失败路径。
```

你可以在本地群聊页面查看真实发言、草稿、审核和最终结论。

## 开始使用

需要 Python 3.9+，以及受邀 agent 已安装并配置好的本地 CLI。
只有发起端需要安装 skill；原主持人不需要另开一个 CLI 会话。

在需要使用的项目目录执行，按提示选择发起端：

```bash
npx skills add iuyaa/agent-meet --skill agent-meet
```

默认安装到当前项目，跨项目使用可加 `-g`。命令安装需要 Node.js 22.20+，
使用现成的 Skills CLI 从仓库安装，不需要手动下载和解压。
安装后仍需发起端能读写文件、执行 Python 命令并等待工具返回。
指定宿主、更新及手动安装方式见[安装说明](docs/INSTALLATION.md)。

保留你正在使用的会话，让它读取该文件，然后直接提出讨论要求。
安装、发现方式因宿主版本而异，Codex 可用 `$agent-meet`；其它宿主也可直接指定技能名称或路径。

## 可以怎样用

**请另一位 agent 检查方案**

```text
使用 agent-meet，请 Codex 检查这个设计的可实施性。
你继续主持，保留我们之前确定的约束，最后给出共识和分歧。
```

谁发起，谁在原会话主持。例如 Claude 可以邀请 Codex，pi 也可以邀请 OpenCode。

**让多个角色参与**

```text
$agent-meet 请产品经理、架构师和业务负责人讨论这个需求，最多 3 轮。
默认使用 Claude，架构师使用 Codex。你负责主持。
```

角色按你的要求创建，数量和职责都可指定；受邀角色未指定后端时默认用 Claude。
同一后端的不同角色使用独立会话。你也可以指定主持人兼任其中一个角色。

**继续同一次讨论**

```text
继续刚才那次讨论，再加两轮，重点解决最后留下的两个问题。
```

追加会沿用原房间和原角色会话。预算用完但仍有关键缺口时，主持人说明理由，由你决定是否追加。

## 讨论如何形成结果

1. **整理背景**：原主持人从当前会话提取问题、约束、已有决策和未知信息，写成简报。
2. **逐轮讨论**：参与者阅读简报和讨论记录，回复观点、依据与疑问；主持人追问和补充背景。
3. **评估是否可结束**：主持人判断证据是否充分，提出草稿，或解释还需讨论什么。
4. **审核并处理最后意见**：参与者审核草稿；主持人逐项记录采纳、已覆盖、未采纳或留待验证的意见。
5. **保存最终结论**：最终稿与意见处理记录一起保存，页面、导出和主持人的汇报都以它为依据。

一般补充由主持人整理归档；改变事实判断、约束或建议方案的修改需要再次送审。
最终结果保留共识、分歧、待验证事项和讨论依据。审核通过不等于所有建议已经过事实验证。

本地页面显示已记录的公开消息，支持 Markdown、折叠、停止和导出。
追问仍在原主持人会话里进行。回复完成并保存后显示，不展示私有推理过程。

每次讨论默认保存在被讨论项目的独立子目录：

```text
项目/.agent-meet/<时间-议题-ID>/discussion.sqlite
```

简报、角色状态及调用记录保存在同一个讨论目录，默认被 Git 忽略。
显式指定存储路径仍有效。备份时完整保留该子目录，以及各 CLI 自己的原生会话资料。

## 使用前了解

- 原主持人保留当前长对话；受邀角色得到的是背景简报，后续复用各自的讨论会话，不会自动获得完整原始聊天。
- 模型调用使用各 CLI 的账户和配置，可能产生相应费用；Meet 本身不提供模型访问。
- 页面用于查看过程和结果，无法唤醒宿主 UI 中已经结束的回合。正常讨论通过同一回合等待工具返回推进。
- 当前自动化验证使用模拟 CLI；真实账户、模型及操作系统组合仍需在本机验证。

升级时保留原房间和状态目录，让当前会话重新读取新版 SKILL.md；不要为了更新而新开一个没有历史的主持人。
旧草稿已获接受但还没处理最后审核意见时，新版会显示“待整理最终结论”。
